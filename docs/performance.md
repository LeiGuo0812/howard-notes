# 性能与页面生命周期

本文记录现有优化机制与后续开发约束，不保存历史测试次数或设备测量流水。性能结论需针对当前数据和实际设备测量。

## 当前机制

| 范围            | 原因                                                        | 调整                                                                                                  |
| --------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 文章侧栏        | 固定定位起点与搜索框不同；可滚动区域高度受旧计算影响        | 从搜索框所在位置开始，使用 CSS sticky；只在实际尺寸变化时更新可用高度                                 |
| 侧栏材质        | CSS 前缀声明顺序导致生产压缩仅保留 WebKit 版本              | 保留标准和 WebKit 两种声明；文章与记忆卡使用一致的背景、描边与阴影                                    |
| 记忆卡时间线    | 时间索引与整套标签同时渲染，索引被长标签列表推后            | 卡片视图显示标签，时间线显示年月；切回卡片恢复原筛选                                                  |
| 文章筛选和分页  | 每次输入或翻页重新排序并搬动全部文章节点                    | 缓存有限的排序结果；仅排序变化时调整顺序，按需更新可见性、日期和分页                                  |
| 公共图谱        | 每页加载 D3、PIXI，未打开也承担加载和解析成本               | 首次打开才加载；保留节点布局、拖动、缩放与访问配色，补上失败重试与导航取消处理                        |
| 阅读页流程图    | 页面切换移除正文后，Mermaid 仍对旧 DOM 测量，造成未处理异常 | 在持续连接的隐藏测量容器完成绘制，仅向当前页面提交输出；离页、主题重绘和放大控件统一清理              |
| 图谱异步初始化  | 关闭或离页后仍可能完成创建 canvas                           | 校验当前页面和初始化代次，及时销毁过期实例                                                            |
| 链接预览        | 每个链接绑定一对事件与清理回调，预览 DOM 不限量             | 改为事件委托，支持新生成链接；最多保留六份预览，离页不追加过期内容                                    |
| 搜索            | 重复 render 后可能叠加事件与 Escape 处理                    | 每次挂载先清理旧处理器，导航仍使用统一清理机制                                                        |
| 鼠标柔光        | 每次指针移动重复查询并设置相同的状态                        | 进入卡片时准备边缘层；移动时即时更新坐标，视觉参数保持原样                                            |
| 页面设置预览    | iframe 再加载整站脚本、内容与图谱；重复移动宿主可能导致重载 | 独立哈希轻量样稿复用主站 CSS，四场景仅合成内容；显示才加载，隐藏释放，不重复插入宿主                  |
| 维护窗口首开    | 等待模块、模板、身份与目录请求完成后才显示窗口              | 先同步显示轻量窗口，首帧后并行加载工作区模块、模板和 CSS；就绪承接位置/全屏，取消打开意图阻止迟到弹回 |
| 维护目录连接    | 并发私密分支重复请求运行配置，模式切换后又渲染一次列表      | 同实例合并在途运行配置请求，失败后重试；共享模块/连接 Promise，连接时列表只渲染一次                   |
| 设置必要数据    | 首开设置也等待完整 Git tree、私密目录、恢复稿和任务元数据   | 身份验证与设置专用 Git 读取并行；固定 commit 下读取设置/目录，个人元数据按需共享准备                  |
| Git 完整元数据  | 分支版本未变时仍重复下载 commit、tree 和目录 blob           | 每次取得 fresh 分支 ref，固定 commit 的元数据在实例内有界复用，返回深拷贝，失败可重试                 |
| 回收站刷新      | 仅查看删除记录也重复读取有效文库、恢复稿和任务              | 读取当前公开 Git 与两类已删除个人目录；永久删除以服务端确认更新当前列表，不等待整库刷新               |
| 编辑器流程图    | 相同图表随文字输入重新生成 SVG                              | 同一编辑器缓存已净化 SVG，最多十二份、约 1 MB；文章切换清空缓存                                       |
| 部署状态        | 浏览器后台标签仍每二十秒查询                                | 标签隐藏时暂停状态查询，回来立即更新；发布任务继续运行                                                |
| 静态资源切换    | 本机构建与线上部署不是同一版本，旧根脚本也可能遗漏          | 按线上资源清单保留多代脚本、字体、带哈希的工作区模板和样式；资源核验完成后才切换模板                  |
| 登录恢复        | 已登录的普通阅读也会加载整个编辑器                          | 会话控制器与维护工作区分离，首次打开窗口才加载表单、编辑器和样式                                      |
| 首页推荐与活动  | 全量推荐模板和隐藏年份增加 HTML 与 DOM                      | 首屏只输出三张推荐及选中年份；其他内容使用紧凑公开数据按需生成                                        |
| 编辑预览        | Marked 与正式 Quartz 语义不同，主线程整篇解析影响输入       | 复用正式 Quartz 编译器的独立 Worker；连续输入合并，过期结果不更新当前预览                             |
| 公共内容服务    | 已发 ETag，但匹配请求仍读取和返回整段正文                   | GET/HEAD 匹配当前版本返回 304；仅查询资源存在性；HEAD 不读取正文                                      |
| GitHub 登录服务 | 身份与仓库权限两个独立请求顺序等待                          | 并行请求，全部验证成功才返回登录凭据，保留原有错误优先级与权限检查                                    |

私密文章及其目录、记忆卡、私密附件和登录会话继续使用原权限检查与 `no-store`；公开 Git 元数据复用不扩展到这些接口，也不改变已有内容的可见性。

## 缓存与扩展边界

HTML 页面另有平台限制：Worker 可以正确响应条件请求，但 workers.dev 线上 HTML 响应没有保留 ETag，浏览器自动重验证的节省尚未确认。[Cloudflare 官方说明](https://developers.cloudflare.com/cache/reference/etag-headers/)指出 HTML 改写可能移除 ETag；目前未确认具体改写原因。保留现有压缩，没有为保留响应头而关闭压缩。

目前不需要重写框架或改变数据库。若文章与记忆卡数量持续增加，可以分别评估：公共搜索索引增量更新、记忆卡可视区渲染、附件采用对象存储、构建阶段进一步增量化。这些会涉及搜索范围、滚动行为、数据迁移或部署方式，应单独设计与验证。

首次进入文章、草稿、私密维护或回收站，仍要准备完整个人元数据（每页 200 条）并核验权限；当前没有按各列表拆分 readiness。编辑器首次下载/解析和 Git 网络仍有成本，并行资源和不可变元数据复用不能消除这些等待。后续可独立评估按功能拆分编辑器、历史与设置依赖，或按列表准备数据；必须先设计关联稿件、冲突和任务依赖，不能把未加载条目当作不存在。现行存储架构与鉴权边界保持不变。

继续开发时优先复用页面生命周期清理、受限缓存和后台进度组件。新增异步功能需要覆盖“重复打开、关闭、页面切换、失败重试”四种情况；公共缓存与私密数据权限保持独立。

## 首页与浏览控件

推荐刷新、年份切换和设置预览共用安全 DOM 构造函数；标题与摘要使用文本节点，紧凑 JSON 转义 HTML 特殊字符，不能借优化把私密目录加入公开池。无 JavaScript 时仍保留首屏推荐和选中年份。其他年份切换后替换当前热图，不长期累积隐藏节点。

会话恢复不加载编辑器模板、完整目录或预览 Worker；仅私密阅读路由按需加载私密客户端。鼠标或键盘聚焦维护入口只预热轻量会话控制器。首次点击页面设置、新建、文章管理等窗口入口，由 `admin/maintenance-opening.mjs` 同步创建窗口和左下角进度，两个动画帧后才开始并行加载完整模块、匹配版本的模板和 CSS，避免等模块完成再开始资源请求。设置首次连接并行核验身份与仓库写权限、读取必要的公开设置；全部成功后才可编辑，不再等待私密元数据。不要用预加载整个编辑器或提前启用写入来掩盖首次打开耗时。编辑预览使用独立 Worker 完成解析、公式和高亮，主线程负责图片、Mermaid 查看器及最终挂载；文章切换、退出和销毁会丢弃过期结果。

加载窗口沿用现有浮窗控制，期间可拖动、全屏、还原或收起。完整工作区就绪时承接位置和全屏状态；收起、导航、退出及会话到期取消旧打开意图，迟到结果不能弹回窗口或恢复权限。重复点击共用模块与连接请求，最新选择生效；再次打开已连接工作区沿用实例和编辑缓冲。运行配置请求只在同一个 `PersonalLibrary` 实例内合并，失败后不保留失败 Promise；这种去重不缓存认证结果、令牌或私密正文，也不省略权限验证。

`createMaintenanceAssetLoader().prepare()` 在实际打开工作区时发出模板请求及 CSS preload，与动态模块导入并行。匹配哈希的模板成功后在同一控制器内复用一份，失败清除 Promise 以便重试；未被工作区工厂消费的拒绝也有处理。CSS preload 只预热资源，不等待其 `load` 事件；最终 Shadow DOM 仍通过正式 stylesheet 呈现。样式提示按同一 document/href 去重、有界保留，普通阅读和恢复会话不因此下载完整编辑器。

设置专用 snapshot 使用 fresh 分支 ref 和同一 commit 下的 Contents 响应，验证文件路径、blob SHA、内容与 JSON。只包含设置与公开目录基线，并显式标记 `settingsOnly`；没有文章文件列表，不能用于原文读取、删除或发布。保存仍读取完整 Git snapshot，检查设置 SHA、专题占用及非强制 ref 更新。Worker 公开设置 API 可能落后于 Git 且没有设置 blob SHA，不代替编辑权威。

`GitHubLibrary.snapshot()` 每次重新读取并鉴权当前分支 ref，再按仓库和不可变 commit 在客户端实例内复用完整元数据；最多保留三份，包含共享在途 Promise。新 commit 重新读取 commit/tree 和目录字节，校验失败删除相应缓存，下一次可以重试。返回 `structuredClone()` 分开 Map、目录项和设置，调用方不能污染下一次取得的远端基线；不持久存储可变分支、凭据或 D1 私密数据。

只查看设置时不主动加载完整文库。首次进入文章维护功能或需要监测、重试发布任务时，通过共享 `ensureSnapshot()` 在后台准备完整 Git 与个人目录、恢复稿、任务元数据。完整读取才设置 `personalReady`；文章动作等待同一过程，不据未就绪的空数组推断草稿或私密内容不存在。补齐不调用 `settings.load()`，不重置布局草稿和原 SHA；已成功保存的新公共基线优先，日常刷新仍保持 fresh 读取。退出或过期取消迟到赋值与旧轮询，重认证保留编辑缓冲，但不恢复无效凭据。

文章管理、私密文章、新建、草稿箱、回收站和页面设置的普通浮窗，以及对应加载窗口，都支持点击窗口外部收起。`admin/panel-outside-close.mjs` 使用事件的 `composedPath()` 判断 Shadow DOM 内部点击，保留布局草稿、文章缓冲及基线；拖动/滚动、维护按钮、左下角进度和上层弹层不误触，外部页面控件继续执行原操作。原位阅读编辑及其全屏形式不启用该行为。收起取消待打开意图，不等于取消编辑或发布。

回收站的恢复和永久删除按提交时的操作来源保持窗口，方便连续处理；不以晚到结果到达时所在的标签决定是否收起。用户主动收起或导航后，完成提示只更新进度和记录，不能把窗口重新打开。发布、保存草稿及移入回收站仍沿用自动收起和左下角后台进度。

回收站刷新只调用 `publicSnapshot()` 和对应的 `listTrash()`，后者读取回收站状态的私密文章与云恢复稿目录；不额外取得有效私密文章、有效恢复稿和发布任务。赋值前校验客户端及会话代次，不能让退出后的迟到结果覆盖列表。`purgeTrash()` 以已确认的 Git 提交或认证 D1 回应更新相关记录和缓存，保留版本检查、UUID 幂等保护及完整基线标记，不为确认成功再次等待整库 `snapshot()`。

设置样稿 iframe 使用与主站构建相同的哈希 CSS、独立轻量渲染器和少量固定合成内容，提供首页、专题、文章列表、阅读页四场景。只传经白名单投影的品牌、设计与布局字段，不读真实 catalog、原文、私密目录或图床配置；不加载主站登录、搜索、图谱、记忆卡客户端或内容 Worker，子页 `connect-src 'none'`。场景切换复用同一文档，明暗切换不重建样稿内容，隐藏释放 iframe；版本化 HTML 通过维护清单 `sitePreviewEntry` 纳入多代资源保留。样稿能比较配色、字体和布局，不是完整主站复刻，也不验证真实内容、搜索、分页、登录或发布。

首开性能检查要分别测量首个可见窗口与设置就绪。在隔离浏览器使用合成会话，独立延迟模块、模板、认证、必要 Git 设置和个人目录请求，检查浅深主题及 390/768/1440px。窗口应先出现、控件可操作，完整工作区接替后位置不跳动；个人目录慢或失败时设置仍可编辑。连续点击、外部收起、重开、离页、退出/到期及失败重试均不得重复绑定或让旧意图生效。再检查后台补齐不丢布局草稿、期间设置保存不回退、文章操作等待完整基线、重开保留未保存内容。记录延迟条件和实际范围，不承诺所有设备的固定毫秒数，不把占位响应写成数据已完成加载。

- 首页预览使用独立的小控制器，显示四张可见记忆卡的纯文本摘要，不加载记忆卡完整编辑器、Markdown 渲染器或附件。退出登录、离开页面及浏览器恢复页面时，清除旧结果并取消过期请求；没有更改数据库内的原文和可见性。
- 文章与记忆卡共用分页标记、页码校验、事件委托和样式；只有页数或当前页变化时重建页码按钮。重复挂载先清理旧监听，离页解绑。记忆卡请求期间可继续选择新页，旧请求取消，响应不会覆盖更新后的选择。
- 记忆卡编辑器的输入监听由编辑器自身清理，并在销毁时释放输入、预览、附件引用和标签控件；暂时收起窗口仍保留编辑内容。
- 标签提示只匹配已授权的内存元数据，最多显示八项，不逐键请求；记忆卡独立标签索引共享在途读取，保存或可见性变化后重新取得，退出和销毁清理。图片设置只在实际上传时读取固定 Git 版本的设置文件，不初始化文章文库；同一授权期间复用，站点内容变更、身份变化或退出失效。上传队列按批串行、文件之间让出执行；文本编辑、拖动和收起不被整窗锁定，只有依赖上传完成的卡片动作等待。哈希、编码和 Git 网络仍有实际成本，不承诺关页后浏览器上传继续。
- 侧栏只在尺寸变化时重新测量，不增加常驻滚动循环。全站位置按钮保留减少动态效果设置；点击到底时，最多短暂观察三秒内的晚到流程图和图片布局，任何手动交互或导航都会立即停止。
- 旧页面设置中的首页标签模块迁移为记忆卡预览，首页浏览模块移除。文章与记忆卡各自的标签、专题路由、旧内容和设置草稿继续兼容。

后续按实际数据量评估记忆卡可视区渲染和专用轻量预览接口。首页复用二十条分页接口，只展示四条；不得为预览扩大私密读取范围。资源、CPU 和耗电取决于设备、数据、图表与动效，不能把玻璃站点等同纯文本页面的占用。

## 发布与版本兼容

旧标签页可能延迟打开编辑器或图谱。部署保留当前版本及至少两个旧版本，并尽量覆盖最近 24 小时，最多八代；超出 5000 个运行资源或 200 MiB 则停止部署供维护者检查。保留窗口有界，超过窗口的旧标签页可能需要先保存草稿再刷新，不强制重载编辑内容。固定入口仅为兼容保留，新工作区将模板、样式和脚本绑定到同一内容哈希版本。

Pages 对纯说明文档变更跳过构建部署；每次实际发布，包括定时和仅文章变更，仍通过完整发布测试、类型检查、构建和隐私检查。Cloudflare 主站使用统一部署工具，源码提交与远端 main 一致才继续。工具核对真实线上依赖并应用版本化迁移，完成资源验证后切换 D1 页面模板；不能拿本机上次构建目录替代真实线上版本。

私密文章元数据逐页加载，每页 200 条，不再以单次 5000 条作为完整目录。记忆卡时间线每页最多 100 条，年份月份来自服务器按当前权限和筛选条件聚合，月份跳转直接请求该月；未获授权的记录不会进入访客月份计数。
