# 性能与页面生命周期

本文记录现有优化机制与后续开发约束，不保存历史测试次数或设备测量流水。性能结论需针对当前数据和实际设备测量。

## 当前机制

| 范围            | 原因                                                            | 调整                                                                                     |
| --------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 文章侧栏        | 固定定位起点与搜索框不同；可滚动区域高度受旧计算影响            | 从搜索框所在位置开始，使用 CSS sticky；只在实际尺寸变化时更新可用高度                    |
| 侧栏材质        | CSS 前缀声明顺序导致生产压缩仅保留 WebKit 版本                  | 保留标准和 WebKit 两种声明；文章与记忆卡使用一致的背景、描边与阴影                       |
| 记忆卡时间线    | 时间索引与整套标签同时渲染，索引被长标签列表推后                | 卡片视图显示标签，时间线显示年月；切回卡片恢复原筛选                                     |
| 文章筛选和分页  | 每次输入或翻页重新排序并搬动全部文章节点                        | 缓存有限的排序结果；仅排序变化时调整顺序，按需更新可见性、日期和分页                     |
| 公共图谱        | 每页加载 D3、PIXI，未打开也承担加载和解析成本                   | 首次打开才加载；保留节点布局、拖动、缩放与访问配色，补上失败重试与导航取消处理           |
| 阅读页流程图    | 页面切换移除正文后，Mermaid 仍对旧 DOM 测量，造成未处理异常     | 在持续连接的隐藏测量容器完成绘制，仅向当前页面提交输出；离页、主题重绘和放大控件统一清理 |
| 图谱异步初始化  | 关闭或离页后仍可能完成创建 canvas                               | 校验当前页面和初始化代次，及时销毁过期实例                                               |
| 链接预览        | 每个链接绑定一对事件与清理回调，预览 DOM 不限量                 | 改为事件委托，支持新生成链接；最多保留六份预览，离页不追加过期内容                       |
| 搜索            | 重复 render 后可能叠加事件与 Escape 处理                        | 每次挂载先清理旧处理器，导航仍使用统一清理机制                                           |
| 鼠标柔光        | 每次指针移动重复查询并设置相同的状态                            | 进入卡片时准备边缘层；移动时即时更新坐标，视觉参数保持原样                               |
| 页面设置        | 不可见时也加载完整站点 iframe；重复移动同一宿主导致 iframe 重载 | 设置预览显示时才加载，隐藏时释放子页面；宿主父节点未变化时不重新插入                     |
| 维护窗口首开    | 等待模块、模板、身份与目录请求完成后才显示窗口                  | 先同步显示轻量窗口，首帧后加载完整工作区；就绪承接位置/全屏，取消打开意图阻止迟到弹回    |
| 维护目录连接    | 并发私密分支重复请求运行配置，模式切换后又渲染一次列表          | 同实例合并在途运行配置请求，失败后重试；共享模块/连接 Promise，连接时列表只渲染一次      |
| 编辑器流程图    | 相同图表随文字输入重新生成 SVG                                  | 同一编辑器缓存已净化 SVG，最多十二份、约 1 MB；文章切换清空缓存                          |
| 部署状态        | 浏览器后台标签仍每二十秒查询                                    | 标签隐藏时暂停状态查询，回来立即更新；发布任务继续运行                                   |
| 静态资源切换    | 本机构建与线上部署不是同一版本，旧根脚本也可能遗漏              | 按线上资源清单保留多代脚本、字体、带哈希的工作区模板和样式；资源核验完成后才切换模板     |
| 登录恢复        | 已登录的普通阅读也会加载整个编辑器                              | 会话控制器与维护工作区分离，首次打开窗口才加载表单、编辑器和样式                         |
| 首页推荐与活动  | 全量推荐模板和隐藏年份增加 HTML 与 DOM                          | 首屏只输出三张推荐及选中年份；其他内容使用紧凑公开数据按需生成                           |
| 编辑预览        | Marked 与正式 Quartz 语义不同，主线程整篇解析影响输入           | 复用正式 Quartz 编译器的独立 Worker；连续输入合并，过期结果不更新当前预览                |
| 公共内容服务    | 已发 ETag，但匹配请求仍读取和返回整段正文                       | GET/HEAD 匹配当前版本返回 304；仅查询资源存在性；HEAD 不读取正文                         |
| GitHub 登录服务 | 身份与仓库权限两个独立请求顺序等待                              | 并行请求，全部验证成功才返回登录凭据，保留原有错误优先级与权限检查                       |

私密记忆卡、私密附件和登录会话继续使用原权限检查与 `no-store`；公共缓存调整没有扩展到这些接口。没有更改现有数据的公开状态，也没有执行文章或记忆卡发布、删除操作。

## 缓存与扩展边界

HTML 页面另有平台限制：Worker 可以正确响应条件请求，但 workers.dev 线上 HTML 响应没有保留 ETag，浏览器自动重验证的节省尚未确认。[Cloudflare 官方说明](https://developers.cloudflare.com/cache/reference/etag-headers/)指出 HTML 改写可能移除 ETag；目前未确认具体改写原因。保留现有压缩，没有为保留响应头而关闭压缩。

目前不需要重写框架或改变数据库。若文章与记忆卡数量持续增加，可以分别评估：公共搜索索引增量更新、记忆卡可视区渲染、附件采用对象存储、构建阶段进一步增量化。这些会涉及搜索范围、滚动行为、数据迁移或部署方式，应单独设计与验证。

继续开发时优先复用页面生命周期清理、受限缓存和后台进度组件。新增异步功能需要覆盖“重复打开、关闭、页面切换、失败重试”四种情况；公共缓存与私密数据权限保持独立。

## 首页与浏览控件

推荐刷新、年份切换和设置预览共用安全 DOM 构造函数；标题与摘要使用文本节点，紧凑 JSON 转义 HTML 特殊字符，不能借优化把私密目录加入公开池。无 JavaScript 时仍保留首屏推荐和选中年份。其他年份切换后替换当前热图，不长期累积隐藏节点。

会话恢复不加载编辑器模板、完整目录或预览 Worker；仅私密阅读路由按需加载私密客户端。鼠标或键盘聚焦维护入口只预热轻量会话控制器。首次点击页面设置、新建、文章管理等窗口入口，由 `admin/maintenance-opening.mjs` 同步创建窗口和左下角进度，两个动画帧后才开始完整模块和目录加载；设置可编辑仍需等待请求完成。不要用预加载整个编辑器来掩盖首次打开耗时。编辑预览使用独立 Worker 完成解析、公式和高亮，主线程负责图片、Mermaid 查看器及最终挂载；文章切换、退出和销毁会丢弃过期结果。

加载窗口沿用现有浮窗控制，期间可拖动、全屏、还原或收起。完整工作区就绪时承接位置和全屏状态；收起、导航、退出及会话到期取消旧打开意图，迟到结果不能弹回窗口或恢复权限。重复点击共用模块与连接请求，最新选择生效；再次打开已连接工作区沿用实例和编辑缓冲。运行配置请求只在同一个 `PersonalLibrary` 实例内合并，失败后不保留失败 Promise；这种去重不缓存认证结果、令牌或私密正文，也不省略权限验证。

首开性能检查要分别测量首个可见窗口与设置就绪。在隔离浏览器使用合成会话，延迟模块、模板、认证和目录请求，检查浅深主题及 390/768/1440px。窗口应先出现、控件可操作，完整工作区接替后位置不跳动；连续点击、收起后重开、离页、退出/到期及失败重试均不得重复绑定或让旧意图生效。再检查已连接窗口的重开及未保存内容保留。记录延迟条件和实际范围，不承诺所有设备的固定毫秒数，不把占位响应写成数据已完成加载。

- 首页预览使用独立的小控制器，显示四张可见记忆卡的纯文本摘要，不加载记忆卡完整编辑器、Markdown 渲染器或附件。退出登录、离开页面及浏览器恢复页面时，清除旧结果并取消过期请求；没有更改数据库内的原文和可见性。
- 文章与记忆卡共用分页标记、页码校验、事件委托和样式；只有页数或当前页变化时重建页码按钮。重复挂载先清理旧监听，离页解绑。记忆卡请求期间可继续选择新页，旧请求取消，响应不会覆盖更新后的选择。
- 记忆卡编辑器的输入监听由编辑器自身清理，并在销毁时释放输入、预览、附件引用和标签控件；暂时收起窗口仍保留编辑内容。
- 侧栏只在尺寸变化时重新测量，不增加常驻滚动循环。全站位置按钮保留减少动态效果设置；点击到底时，最多短暂观察三秒内的晚到流程图和图片布局，任何手动交互或导航都会立即停止。
- 旧页面设置中的首页标签模块迁移为记忆卡预览，首页浏览模块移除。文章与记忆卡各自的标签、专题路由、旧内容和设置草稿继续兼容。

后续按实际数据量评估记忆卡可视区渲染和专用轻量预览接口。首页复用二十条分页接口，只展示四条；不得为预览扩大私密读取范围。资源、CPU 和耗电取决于设备、数据、图表与动效，不能把玻璃站点等同纯文本页面的占用。

## 发布与版本兼容

旧标签页可能延迟打开编辑器或图谱。部署保留当前版本及至少两个旧版本，并尽量覆盖最近 24 小时，最多八代；超出 5000 个运行资源或 200 MiB 则停止部署供维护者检查。保留窗口有界，超过窗口的旧标签页可能需要先保存草稿再刷新，不强制重载编辑内容。固定入口仅为兼容保留，新工作区将模板、样式和脚本绑定到同一内容哈希版本。

Pages 对纯说明文档变更跳过构建部署；每次实际发布，包括定时和仅文章变更，仍通过完整发布测试、类型检查、构建和隐私检查。Cloudflare 主站使用统一部署工具，源码提交与远端 main 一致才继续。工具核对真实线上依赖并应用版本化迁移，完成资源验证后切换 D1 页面模板；不能拿本机上次构建目录替代真实线上版本。

私密文章元数据逐页加载，每页 200 条，不再以单次 5000 条作为完整目录。记忆卡时间线每页最多 100 条，年份月份来自服务器按当前权限和筛选条件聚合，月份跳转直接请求该月；未获授权的记录不会进入访客月份计数。
