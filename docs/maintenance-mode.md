# 主站维护模式

主站与 `/admin/` 共用 `admin/workspace.mjs`，不从已渲染 HTML 还原笔记。所有功能继续通过既有 GitHub 文库服务完成；文章正文、目录和站点设置保持各自的保存边界。

## 使用路径

- 主站顶栏登录 → GitHub 授权 → 返回原地址、查询参数、锚点和阅读位置。
- 阅读文章 → 编辑文章 → Markdown 格式工具及本机实时预览 → 存草稿或发布。
- 新建、草稿箱、文章管理、页面设置在主站面板打开，支持收起后继续阅读。
- 顶栏「已登录」仅显示登录状态；首页使用图标加文字的维护按钮，阅读页的维护工具位于右侧，文章右上角的编辑图标打开原位编辑器。
- 维护面板支持全屏与还原；桌面可拖动标题栏调整浮窗位置。窗口操作与文章缓冲区分开，移动端使用可触达的全屏控件。
- 手机默认编辑视图，可切换预览；桌面并排编辑与预览。
- 文章正文的双链和外链在新标签页打开；导航栏、文章列表和目录保持原浏览方式。
- 已发布文章的修改草稿仍独立保存，公开原文仅在发布时更新。发布后按保存提交 SHA 查询 Pages 构建状态。
- 已发布文章的编辑器提供「删除文章」；编辑它的修改草稿时提供「删除已发布文章」。确认后同时删除网站文库中的原文及关联修改草稿，并显示部署进度；「删除草稿」仍只删除当前草稿。
- 未发布文章（包括撤下的文章）与远端草稿均通过「删除草稿」删除。本机恢复记录也可删除；原远端已不存在时显示「删除本地草稿」，只清理浏览器记录。

## 组件边界

| 文件                                            | 职责                                           |
| ----------------------------------------------- | ---------------------------------------------- |
| `quartz/components/Blog.tsx`                    | 提供登录、维护操作、文章 ID 和编辑挂载位置     |
| `admin/maintenance-loader.mjs`                  | 轻量入口、按需获取版本清单并加载维护组件       |
| `admin/maintenance.mjs`                         | 主站会话、命令、面板挂载与 Quartz 导航生命周期 |
| `admin/panel-window.mjs`                        | 浮窗位置、全屏切换及视口边界，不保存文章状态   |
| `admin/workspace.mjs`                           | 文章、草稿、格式、图片、设置共用控制器         |
| `admin/app.mjs`                                 | 独立后台启动及同一个工作区的登录接线           |
| `admin/auth.mjs` / `auth-service/worker.mjs`    | GitHub 所有者登录、一次性结果领取及安全回跳    |
| `admin/github.mjs`                              | 原 Markdown、原子提交、SHA 和目录冲突检查      |
| `admin/article-recovery.mjs`                    | 本机文章恢复稿及原始版本基线                   |
| `admin/settings.mjs` / `admin/site-preview.mjs` | 设置表单、布局草稿和真实页面预览               |
| `admin/deployment.mjs`                          | 按本次提交读取 Pages 工作流状态                |
| `scripts/build-maintenance.mjs`                 | 共用表单生成、Shadow DOM 样式及版本化入口      |

访客只加载轻量启动器。编辑器、预览依赖、GitHub 文库、原文章与草稿均在维护模式按需获取。独立后台和主站分别构建入口，但使用同一套源码和同一份 `admin/index.html` 表单。

维护工作区使用 Shadow DOM 隔离样式与 ID；输入锁定仅作用于工作区。Quartz 在 `prenav` 时拆下维护宿主，在 `nav` 时重新挂载同一个宿主，避免 `micromorph` 替换编辑器；会话、撤销历史和未保存缓冲区因此保留。编辑原文章时挂到正文位置，导航到其他页面时以面板继续保留。

## 扩展接口

`createWorkspace(root, options)` 接受站点根 URL、会话变化、重认证、关闭、保存完成等回调。返回文章打开、新建、模式切换、忙碌状态、关闭、退出与销毁等方法。公开会话信息只有账号和时间，不包含令牌。`onSaved({ kind, articleId?, removedIds?, scope?, commit? })` 可用于部署状态和后续版本历史功能；删除回调包括原文和关联草稿的 ID、返回的文章或草稿列表范围。

主站控制器通过命令表分派操作，`registerCommand(name, callback)` 可增加后续维护入口。新的主站按钮使用 `data-maintenance-action`，无须复制编辑器状态或在阅读组件中加入保存逻辑。域服务继续独立在 GitHub、图床、格式、预览和恢复模块中；迁移服务时可保持工作区与主站挂载接口。

维护窗口在普通面板、全屏与文章原位编辑之间移动同一个宿主，不重建编辑器。桌面标题栏支持指针拖动和方向键移动；窗口缩放后重新限制在视口内。小屏右侧工具菜单按 1240px 断点折叠，选择操作后收起，图标同时提供 `title`、无障碍标签及悬停提示。

首页卡片、目录及导航沿用原有玻璃配色，阅读区单独使用 `--glass-reading: #eef0f2` 灰色底板与 `--glass-reader-page` 页面背景。正文、链接及辅助文字保持独立的前景色，不通过整体透明度降低阅读对比。

## 状态与安全边界

令牌只在当前维护实例内存中，内部导航保留，刷新或关闭页面后需再次登录。手机初次登录采用同页跳转；正在编辑时重认证采用弹窗保留页面。回跳仅允许同源和本站部署路径，路径、查询参数及锚点保存在加密流程中；令牌不进入 URL、布局预览或本机恢复稿。登录返回有效期继续使用服务器时间，主站会话到期判断使用单调时钟。

本机恢复稿保存文章原文、编辑表单、原文章目录项和最初 SHA。恢复时即使远端变化，也不会把旧编辑换成最新基线；现有服务拒绝并发覆盖。恢复存储有数量和大小上限，存储失败时可以下载原稿。输入后短暂合并写入，切后台和离开页面时立即暂存。

浏览器恢复稿只属于当前设备；显式存草稿后才进入 GitHub。公开仓库内的草稿可通过仓库访问，草稿状态只控制网站展示。图片上传仍立即写入已配置图床，取消文章不删除图片。正文的 BOM、CRLF 和既有原文保持原保存规则。

删除文章使用独立的载入版本基线：原文及所有关联草稿的目录项、文件 SHA 都必须保持一致。目录与文件在同一提交删除，分支更新不使用强制覆盖；发生并发更改时保留编辑器和恢复稿。取消确认不更改内容，成功后清除相关本机恢复稿。恢复中的本地编辑不推断新的删除基线，需下载当前编辑并显式重新载入后才能删除远端已发布文章。仅删除修改草稿时保留已发布原文；远端删除成功后即使列表刷新失败，仍清理已删编辑器并显示部署状态。

删除仅作用于网站仓库，保留共享图片、页面设置和无关文章，独立 Obsidian 原始笔记不受影响。本地公开文库镜像的三方同步遇到远端删除时，会默认报告需显式 `--allow-delete` 的冲突；使用该参数会备份并同步镜像中的删除，独立原始笔记仍保留。

## 验证

运行 `npm run test:publish`、`npm run check`、`npm run build`、`npm run verify:site`。发布检查同时验证版本化维护入口、共用无脚本表单、主站登录入口、后台 CSP、文章、RSS 和搜索索引。

浏览器回归使用模拟 GitHub 授权及内存仓库，避免将测试文稿写入公开文库。实体手机的真实授权和真实内容发布需要由所有者使用本站执行，不作为模拟测试通过的结论。

2026-10-01 本次验证记录：166 项发布、认证、恢复与窗口边界测试，以及 4 项渲染链接测试通过；类型与格式检查、完整构建和 298 个 HTML 页面校验通过，公开文章为 173 篇，包含所有者新发布的 `test` 文章。本次实现未改写或删除真实文章。

Chromium 实际浏览器检查覆盖 1440px、768px、390px 及明暗主题：匿名按需加载、同页登录返回原文、编辑与格式预览、内部导航保留相同编辑实例、草稿独立保存、发布冲突保留原稿、草稿发布与清理、退出、旧后台、手机刷新恢复、图片多选和粘贴去重、公式与 Mermaid、长链接/代码/表格、布局拖拽及面板自动滚动、维护面板上的搜索、新标签正文链接。测试仓库写入全部在内存中模拟，无真实文库写入。线上登录 Worker 的自建拒绝授权流程已验证主站回跳和一次性领取；真实 GitHub 所有者授权未代为执行。

维护控件调整另通过 16 项桌面浏览器检查和 12 项 Android 触屏模拟检查：被动登录状态、首页工具按钮、阅读页图标提示、折叠菜单与目录间距、标题栏拖拽与方向键、控制按钮不触发拖拽、视口缩放、四种面板全屏、编辑实例保留、搜索层级及横屏菜单滚动。触屏通过真实浏览器触摸事件验证，不代替实体手机授权。

本次配色与删除通过 23 项 Chromium 浏览器检查，保存 18 张截图。明暗主题在 1440px、768px、390px 验证首页及目录玻璃底色、正文灰色底板与溢出；主站及旧后台验证已发布文章、未发布／撤下文章、修改草稿、独立草稿、新建本机稿及原远端已删除的本机恢复稿。取消删除保留编辑内容，修改草稿删除保留已发布原文；并发版本变化或分支冲突拒绝删除。原文与关联草稿原子删除后跟踪对应提交，后续列表读取失败仍清理已删编辑器及恢复稿。所有仓库写入均由浏览器路由在内存中模拟，未删除真实文章。

## 后台发布与登录保持

公开文章和页面设置仍先写入 GitHub，再原子切换 D1 公开版本。Markdown
编译、页面渲染、差异比较、页面哈希和上传分块在模块 Web Worker 中运行；
GitHub 凭据只留在主线程，不传给渲染线程。线程空闲一分钟后释放。
发布期间继续保留正文输入与预览，窗口可以拖动、全屏、还原或收起；
收起只隐藏界面，发布继续进行。为避免并发覆盖，重复写入仍被禁用。
关掉浏览器会终止当前浏览器任务，待同步标记保留，下次可重试且不重复提交 Git。

Cloudflare 主站提供同源 `/api/content/session`。服务端使用 `SESSION_SECRET`
加密会话，并通过 Secure、HttpOnly、SameSite=Strict Cookie 保存。
恢复会话仍核验 GitHub 账号和仓库写入权限，最大有效期受 GitHub 授权限制为八小时。
刷新主站、新标签页和独立管理页面共享该 Cookie；退出时清除 Cookie。
本地缓存只存自动恢复提示的到期时间，不存令牌，不能凭此提示取得权限。
GitHub Pages 备用域名不会跨域读取主站 Cookie，仍沿用原登录流程。
`SESSION_SECRET` 必须通过 Worker secret 配置，不进入代码、D1 或公开资源。
