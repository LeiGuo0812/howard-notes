# 网页主维护模式：文库边界、发布与长期维护

本文说明个人笔记在网页端维护的架构与操作约定。路径均采用通用占位符，不包含本机真实路径、账户密钥或私密笔记内容。本文记录现行实现与回归流程；线上版本分别查询 Git、Worker 部署和公开内容状态，不保存历史验收流水。

## 原文的权威来源

| 内容                                | 权威来源                          | 谁可以读取                         | 恢复依据                     |
| ----------------------------------- | --------------------------------- | ---------------------------------- | ---------------------------- |
| 已公开文章原文、目录及公开历史      | 网站 GitHub 仓库的 `library`      | 公开仓库中的文件和历史可被访问     | Git 历史、固定提交归档       |
| 未公开文章及私密修改稿              | 认证 D1 的 `personal_articles`    | 固定维护者账号                     | 原文版本历史、独立加密备份   |
| 编辑中的服务端恢复稿                | D1 的 `personal_drafts`           | 固定维护者账号                     | 恢复稿历史、独立加密备份     |
| 记忆卡正文、元数据及可见性          | D1 的记忆卡域                     | 公开卡访客可读，私密卡仅维护者可读 | D1 加密备份                  |
| 私密文章原附件                      | 私有 R2 bucket，D1 保存身份与关联 | 经维护者认证的文件接口             | 原文件 SHA、独立加密对象备份 |
| 明确同意公开的图片及附件            | 独立 GitHub 图床仓库              | 公共链接持有者可读                 | 图床固定提交归档             |
| 公开 HTML、全文索引、专题和图谱投影 | 从公开 Git 原文生成的 D1/静态站点 | 访客可读                           | 可从原文重新构建             |

每篇公开文章继续以 Git 原文为来源。编辑它时，新的修改先保存在私密域并绑定公开基线；发布完成后才替换公开原文。私密副本、修改稿和历史不是另一套可以自行覆盖 Git 的公开主数据。

私密文章的标题、原文、专题、标签和关系不能混入公开 `contentIndex`、RSS、sitemap、静态 HTML、Pages 构建或公共 Git 目录。维护者登录后的统一文库由私密适配器合并显示，访客仍只得到公开投影。

## 私密文章独立阅读

维护者登录后，顶部主导航在“文章”旁显示“私密文章”，而不是在维护操作栏中打开私密列表。`<SITE_BASE>/private/` 是不含个人数据的外壳；`?note=<ARTICLE_ID>` 表示独立阅读选择，可在已登录的新标签页或刷新后继续打开。匿名直接访问只显示登录提示，私密原文 API 仍强制认证。

私密列表和正文只存在于认证读取后的页面内存。完整阅读使用共享 Quartz 编译和文章净化策略，在专用阅读 Worker 中处理原文，授权凭据不进入编译线程，也不调用公开发布投影。正文的编辑图标复用原位编辑器、基线保护与私密保存流程。退出、会话失效和页面卸载时清空原文、标题、附件 Blob 和未完成读取，晚到的响应不得重新填入。

## 登录和权限

网页沿用 GitHub 账号登录，后端核验固定维护者身份及仓库维护权限。浏览器不用手工粘贴令牌。服务端会话与需要继续执行的短期发布授权有明确有效期；到期重新登录后可继续任务，不把“记住登录”解释为永久授权。

所有私密读取、保存、历史、导出、附件下载和备份操作都需要维护者权限，响应使用 `private, no-store`。私密文件经认证接口读取，不使用公共 `r2.dev` 地址。读取接口不会只依赖文章上一个 `published:false` 标记来提供隐私保护。

独立 GitHub App 的安装权限应限定为网站仓库和实际使用的图床仓库。备份与发布程序仅通过已确认的同源 API 发送维护凭据，不向页面提供的任意外站 URL 转发授权。

## 新建、私密修改稿与恢复稿

新文章和迁入的未公开笔记默认进入私密 D1。选择保存私密文章不创建公开 Git 原文，不触发网站公开发布。修改已公开文章时，草稿携带原公开文章的基线信息，暂存期间访客继续读取旧的公开版本。

恢复稿用于减少刷新、手机切后台或跨设备造成的编辑丢失。它保存原始编辑内容及基线，采用请求 UUID 和乐观版本保护；网络故障重试同一操作编号，收到确认前不假定保存成功。恢复稿不会默认写入公共 Git 草稿文件。

检测到另一设备已经修改时，保存返回冲突，保留当前编辑。维护者应先查看远端版本、比较或手动合并，再明确保存；不能自动读取最新版本号并用本机旧稿覆盖。断网时仍应允许保留或下载当前原文；在服务端尚未确认前，跨设备恢复不能承诺包含最后一次输入。

草稿箱、恢复稿、正式原文、历史和回收站是不同用途。恢复稿不能代替已经确认保存的文章；30 天回收站也不能代替独立长期备份。

## 公开和私密的切换

私密转公开采用显式发布：先确认私密原文已经保存，绑定其版本，校验公开基线与原文路径，再把获准公开的内容复制到 Git。已有公开版发生并发变化时停止覆盖，保留私密修改稿。

公开转私密先保存对应的私密原文与版本关系，再提交撤下公开入口的 Git 修改，并等待公开投影真正移除。撤下期间显示待同步，不能因为 Git 已接受提交就宣称访客已经无法读取。若当前私密编辑与公开基线不同，应先保留编辑并核对撤下操作所依据的原文，避免把一次撤下与未确认的覆盖混为一件事。

文章一旦进入公共 Git 历史，改回私密只控制后续站点展示及私密维护入口，不能收回旧 Git 提交、克隆、缓存、搜索记录或读者副本。已经公开的附件同样不能因文章转私密而被保证收回。需要从未公开的内容，必须一开始就存入私密域。

## 附件的权限与原文字节

私密附件先上传私有 R2，身份包含原始 SHA-256、大小、文件名与固定对象键。网页通过受限文件接口预览。它们不会因保存草稿或正文而自动上传公共图床。

发布含私密附件的文章时，需要单独明确同意附件公开。公开图床写入以原字节和哈希校验，记录固定 Git 提交链接。没有明确同意、文件缺失、大小变化、校验失败或仓库权限不足时，停止发布并保留私密原文。

迁移和附件替换尽量通过文章元数据中的源地址映射完成，不为了显示图片而改写本地 Markdown。原文保存、导入、导出及恢复均应保留 UTF-8 的 BOM、CRLF 和全部正文。读取非 UTF-8 或不能逐字节还原的文件时先拒绝，不静默转码。

旧记忆卡中已按维护者选择公开的图床附件继续保持原公开方式；记忆卡本身的可见性与附件的公开状态是两个独立边界。

## 后台持久发布与真实状态

发布操作以 D1 的持久任务记录继续执行，不把完成条件绑定到编辑弹窗或浏览器始终打开。界面应立即响应，后台进度独立展示。任务记录保存固定输入版本、请求编号、状态、检查点、重试时间和失败原因。

公开流程如下：

1. 将原文保存为私密记录，确认版本及字节。
2. 创建受限维护权限下的发布任务，绑定私密版本与公开基线。
3. 按需逐步上传明确获准公开的附件，持久记录地址映射。
4. 以 Git 原子提交修改公开原文及目录，保存固定提交检查点。
5. 由 GitHub Actions 编译公开内容并完成 D1 投影的校验与原子切换。
6. 服务端核对实际公开提交、文章原文 SHA 或撤下结果，再标记任务完成。

公开内容编译由 Node.js/GitHub Actions 执行，避免把完整 Markdown 构建压入免费 Worker 的 CPU 预算。Worker 负责受限的授权、原文操作、状态和重试。附件也需要分步处理，不能把大量文件一次缓冲并上传。

“已保存”“已进入任务”“Git 已提交”“等待网站同步”和“已上线”分别对应不同状态。网络失败允许幂等重试，不能重复创建原文或覆盖并发编辑。授权过期显示需要重新登录；重新登录后恢复原任务。新版本还未公开时，已保存私密内容仍可恢复。

## 迁入本地未上传笔记

迁移前对所有待迁入原文件重新核验盘点 SHA。即使只试迁入少量文章，也先验证整份清单；任何原文在盘点后发生变化，都在首次网络写入之前停止。不同空文件及同正文的不同路径使用不同稳定身份；重复路径或跨系统有歧义的 Unicode 路径先拒绝。

以下命令使用通用路径。盘点文件属于私密资料，应保存在受限目录。

```bash
cd "<WEBSITE_PROJECT>"

# 默认只核验，不登录、不上传、不修改本地原文。
node scripts/import-private-notes.mjs \
  --vault "<OBSIDIAN_VAULT>" \
  --inventory "<PRIVATE_AUDIT_DIRECTORY>/inventory.json" \
  --report "<PRIVATE_AUDIT_DIRECTORY>/dry-run.json"

# 先试迁入少量，默认全部进入私密域。
node --use-env-proxy scripts/import-private-notes.mjs \
  --vault "<OBSIDIAN_VAULT>" \
  --inventory "<PRIVATE_AUDIT_DIRECTORY>/inventory.json" \
  --site "https://<SITE_HOST>/<SITE_PREFIX>/" \
  --limit 3 --apply \
  --report "<PRIVATE_AUDIT_DIRECTORY>/trial.json"
```

试迁入后逐篇读取远端原文，核对原始 SHA、时间、标签及私密状态，再去掉 `--limit` 分批迁入全部。重复迁入相同原文不新增版本；已经在网页修改的文章不能被旧清单覆盖，冲突时停止并先核对，不以“同步失败”为理由强制重写。

原始 Obsidian 库保留不动，不因迁入成功删除或改写。清单、报告和本地缓存不得进入公开仓库，尤其不能把内网地址、凭据线索或私密标题随盘点材料一起公开。

## 网页为主、本机只读

运行配置中的 `maintenanceMode: "web-primary"` 将网页设为主维护入口。本地旧双向同步的 `--apply` 会在写入前拒绝，防止旧库覆盖网页新版本。源码开发、网站构建与部署仍由网站仓库承担，但正文的日常编辑转到网页。

需要在本机阅读、整理离线副本或留存原文时，只做单向只读导出，写入一个新的独立私密目录：

```bash
node --use-env-proxy scripts/export-personal-notes.mjs \
  --site "https://<SITE_HOST>/<SITE_PREFIX>/" \
  --output "<NEW_PRIVATE_EXPORT_DIRECTORY>"
```

导出包括私密原文、版本、恢复稿与附件元数据。各页、各表及最后检查均绑定同一个写入 generation；远端在导出期间变化时停止，不写成功 manifest。已有导出目录不会被覆盖，也不会将其内容反向上传。

这份导出是受限目录中的明文阅读副本，不是加密备份，也不包含附件二进制。没有成功 manifest 的目录是未完成导出。即使具有一致性标记，也不能替代离站加密副本及实际恢复演练。

## 备份和恢复

服务器完整密文由私有 GitHub Actions 每日自动离站复制，同时归档源码、图床完整 Git refs 和私库已提交交接材料。专用 `BACKUP_EXPORT_KEY` 只可 GET 导出状态及指定完整密文，不能读取明文或触发备份；维护者状态/运行/下载接口仍要求本人登录。详见 [离站备份](offsite-backups.md)。

规范 D1 数据与私密 R2 原文件由独立加密备份覆盖；公共 HTML 可再生，登录会话、同步临时数据和短期任务凭据排除。备份通过写入 epoch 确认分页读取一致，逐页密文、字节数与 SHA 可核验。

Cloudflare 同账户的独立私有 R2 有助于抵御数据库误删，但不承担账户整体故障隔离。应定期将完整加密包与固定 Git 原文/图床归档复制到另一台设备或另一服务商，恢复密钥单独安全保存。普通浏览器缓存不是备份。

恢复先在新的本地 SQLite 与私密附件目录演练，核对逐字节原文、版本、时间、可见性、SHA 和完整性。不能把“导出了文件”当作“已证明能够恢复”，也不直接覆盖生产库来做日常验证。具体命令和保留规则见 `docs/longterm-backup-recovery.md`。

## 前端与后续开发约定

沿用现有 Quartz、浏览器模块、私密存储适配器和增量公开投影。权限与业务状态在存储/API 层保证，组件负责显示；不要用隐藏按钮、前端标签或透明卡片来代替鉴权。

保留现有页面路由、搜索、标签、专题、目录、图谱、主题切换和维护浮窗。阅读正文保持稳定、不透明度较高、对中文长文友好；进度及维护操作独立于正文，不用同步阻塞覆盖整个页面。正式阅读、预览和嵌入统一执行安全净化，Markdown 原文仍保存原字节。

扩展新内容类型时，先定义权威存储、私密与公开边界、乐观版本、幂等键、历史及回收策略，再更新适配器与备份范围。新增包含凭据的运维表不自动加入长期备份；新增规范内容表必须有 epoch 写入触发器及恢复测试。

## 需要实际验收的项目

代码测试不能代替生产权限和设备检查。正式交付至少分别记录：

- 已登录和未登录的私密列表、原文、附件、历史、导出与备份权限。
- 原文试迁入、完整迁入、重复迁入和网页更新后的冲突保护。
- 新文章、旧文章修改稿及记忆卡在手机刷新、切后台、断网和跨设备后的恢复行为。
- 公开和私密双向切换后的访客索引、文章入口、原文 SHA 与历史边界。
- 发布后关闭浏览器仍能继续，过期授权可登录恢复，真实上线状态可核验。
- 加密副本下载、离站固定 Git 归档、隔离 SQLite 和私密文件的实际恢复校验。
- 桌面和移动端阅读、编辑、预览、目录、搜索、图片和长内容布局回归。

未执行的项目应明确列为待验证，不用测试总数、成功提交或单个页面截图替代整个维护流程的验收。
