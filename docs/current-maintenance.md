# 网站现行维护入口

网页是日常原文维护入口；原 Obsidian 库保留，旧双向写入已关闭。当前系统为 Quartz 5 + Cloudflare Workers/Static Assets/D1 + 私有 R2 + GitHub 公开原文/图床 + 私有 GitHub 离站备份。GitHub Pages 是独立发布的静态备用站。

## 每次修改后

1. 检查当前源码、工作区修改和线上状态；沿用已部署架构。
2. 按变更范围检查：文档执行解析、命令语法、链接与保密检查；程序执行项目检查/测试/构建；界面变更实际查看浏览器。未执行项目明确说明。
3. 提交推送源码。需要更新程序时另外部署 Cloudflare Worker/Assets，再同步页面外壳；Pages 工作流不能替代主站部署。
4. 更新两份现行中文手册、资产映射及恢复步骤，推送私库；云端任务不能读取未推送的本机文件。
5. 运行私库备份任务，核对已发布的完整 Release 及文件校验；源码/图床完整 refs 有变化才新增归档。
6. 清理过期测试日志和临时构建。保留原笔记、导入原始包、实际配置、密钥和未解决冲突，不删除当前线上资源引用。

## 日常检查

每周检查服务器成功快照和 GitHub 离站成功时间；重要变更前先完成新快照再补跑离站任务。定期在可信设备进行隔离恢复，并检查存储/运行用量。内容快照保留近 30 天及最近 12 个实际有备份月份的代表；不可变仓库归档长期保留。原恢复密钥和账号恢复资料另行保管。

## 版本与记录

本文只维护现行流程，不累积历史验收日志。源码版本查看 Git，生产程序查看 Worker 部署，公开内容查看站点 `api/content/status`，备用站查看 Pages Actions，备份查看对应 manifest/receipt。这些对象分别核验，不能假设一个提交意味着所有环境已更新。

备份清单和 SHA 收据是完整性机制，不因整理说明文档而删除。长期保留策略继续作用于实际备份；清理旧本机日志不改变线上文章及云端数据。
